# Контракт Sufficiency Gate

Нормативная лексика по RFC 2119 / BCP 14: **ДОЛЖНО** (MUST), **НЕ ДОЛЖНО** (MUST NOT),
**СЛЕДУЕТ** (SHOULD), **НЕ СЛЕДУЕТ** (SHOULD NOT), **МОЖНО** (MAY).
Термины определены в [`glossary.md`](glossary.md) и здесь не переопределяются.

## Стороны и область

| Сторона | Роль |
| --- | --- |
| Поставщик | Sufficiency Gate |
| Потребитель | Analysis |
| Вход | контекст, собранный Graph / Context Builder и Vector Index |
| Владелец контракта | G-Ivan-A |

**Область:** определение достаточности контекста для рассуждения, действия при недостаточности и
форма явного отказа.

**Вне области:** отбор источников ([relevance-gate-contract](relevance-gate-contract.md)), предметная
аналитика.

## Обязательства

### O-1. Предмет оценки

Gate **ДОЛЖЕН** оценивать достаточность контекста **для ответа на вопрос направления**, а не наличие
данных как таковых. Непустой контекст **НЕ ДОЛЖЕН** сам по себе трактоваться как достаточный.

### O-2. Критерии достаточности

Оценка **ДОЛЖНА** учитывать как минимум:

| Критерий | Что проверяется |
| --- | --- |
| `question_coverage` | доля подвопросов направления, обеспеченных evidence |
| `evidence_density` | число независимых источников на ключевое утверждение |
| `source_diversity` | независимость источников друг от друга |
| `conflict_level` | наличие противоречащих утверждений |
| `uncertainty_ratio` | доля связей в состоянии `UNCERTAIN` |

### O-3. Форма решения

Gate **ДОЛЖЕН** возвращать `SufficiencyDecision` с полями `decision` ∈ {`sufficient`,
`insufficient`, `zero`}, `criteria_scores`, `gaps`, `iteration`, `reason`, `decided_at`.

### O-4. Действия при недостаточности

При `insufficient` и неисчерпанном бюджете gate **ДОЛЖЕН** инициировать одно или несколько действий:
уточняющий запрос, расширение сбора по выявленным `gaps`, повторный проход Relevance Gate по уже
сохранённым материалам Source Intelligence.

### O-5. Явный ZERO

При исчерпании бюджета итераций или источников gate **ДОЛЖЕН** вернуть `zero` с перечнем `gaps`.
Передача заведомо недостаточного контекста в Analysis **НЕ ДОЛЖНА** выполняться. Формулировка
«ответить тем, что есть» **НЕ ДОЛЖНА** применяться как способ обхода `zero`.

### O-6. Ограничение цикла

Цикл `insufficient → расширение → повторная оценка` **ДОЛЖЕН** быть ограничен `max_iterations` и
бюджетом стоимости из конфигурации направления. Выход по любому из лимитов даёт `zero`.

### O-7. Прогресс между итерациями

Если итерация не увеличила `question_coverage`, gate **НЕ ДОЛЖЕН** повторять то же действие
расширения; **СЛЕДУЕТ** сменить стратегию либо завершиться `zero`.

### O-8. Передача в Analysis

При `sufficient` gate **ДОЛЖЕН** передать Context Package, включающий использованные claims с их
`evidence`, состояния связей и итоговое `criteria_scores`. Утверждение без evidence **НЕ ДОЛЖНО**
попадать в Context Package.

### O-9. Телеметрия

Каждая итерация **ДОЛЖНА** порождать запись телеметрии с номером итерации, решением, накопленной
стоимостью и значениями критериев.

### O-10. Точка human-in-the-loop

Gate **ДОЛЖЕН** предоставлять точку вмешательства человека. В MVP — заглушка с логированием; на фазе
S2 роадмапа она становится обязательным gate.

## Конфигурация

```yaml
sufficiency:
  thresholds:
    question_coverage: 0.75
    evidence_density: 2
    source_diversity: 0.5
    conflict_level_max: 0.2
    uncertainty_ratio_max: 0.3
  budget:
    max_iterations: 3
    max_cost_rub: 150
  on_exhaustion: zero
```

## Definition of Done / критерии соответствия

| Критерий | Проверка |
| --- | --- |
| Недостаточный контекст даёт `zero`, а не ответ | обязательный негативный тест |
| Цикл расширения ограничен `max_iterations` | тест на зацикливание |
| Бюджет стоимости соблюдён | тест с искусственно низким бюджетом |
| `gaps` заполнены при `insufficient` и `zero` | контрактный тест |
| Context Package не содержит утверждений без evidence | контрактный тест |
| Итерация без прогресса не повторяет ту же стратегию | тест стратегии расширения |

## Эскалация и исключения

1. **Противоречивые источники выше `conflict_level_max`.** Решение `insufficient` с `gaps`
   типа `conflict`; автоматический выбор «более авторитетного» источника **НЕ ДОЛЖЕН** выполняться
   без human-in-the-loop.
2. **Исчерпание бюджета стоимости раньше итераций.** Возвращается `zero` с указанием причины
   `budget_exhausted`.
3. **Понижение порогов.** Выполняется только изменением конфигурации направления в PR с
   обоснованием; понижение порога в рантайме ради получения ответа **НЕ ДОЛЖНО** происходить.
4. **Переопределение `zero` человеком.** Допустимо через human-in-the-loop и фиксируется в
   телеметрии как `hitl: override` с автором решения.

## Обоснование и контекст

Sufficiency Gate — ключевой элемент IP проекта. Он закрывает конкретный отказ типового пайплайна:
модель, получившая неполный контекст, не отказывается отвечать, а достраивает недостающее. Явный
`zero` переводит этот отказ из скрытого в наблюдаемый.

Ограничение цикла и бюджета введено против сценария «бесконечное расширение сбора ради достижения
порога», который превращает исследовательский прогон в неконтролируемые расходы
([ADR-002](../adr/2026-08-adr-002-model-routing.md)).

Требование evidence для каждого утверждения в Context Package замыкает цепочку провенанса от
источника до входа в аналитическую модель.
