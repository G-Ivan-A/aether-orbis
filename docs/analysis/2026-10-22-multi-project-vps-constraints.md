# Мульти-проектный VPS: анализ бэклога, конфликтов с ADR и внешних ограничений

Документ — доказательная база для
[RFC: Общая платформа развёртывания нескольких ИИ-проектов](../rfc/2026-10-multi-project-vps-platform.md),
[ADR-007](../adr/2026-10-adr-007-multi-project-deployment-topology.md) и
[ADR-008](../adr/2026-10-adr-008-inter-project-api-contract.md). Источник задачи — issue
[#44](https://github.com/G-Ivan-A/aether-orbis/issues/44) и приложенный к ней диалог фаундера от
2026-10-21.

Документ фиксирует **что обнаружено** — состояние репозитория, конфликты, факты о провайдерах и
регулировании. **Что предлагается** — в RFC, **что решено и почему** — в ADR.

## 1. Новая вводная

На одном VPS параллельно работают минимум три независимых ИИ-проекта: `aether-orbis`, проект
автоматизации БА-процессов и третий проект. Из этого следуют четыре требования, которых не было в
изолированном MVP:

1. один проект не должен исчерпать CPU / RAM / диск хоста и положить остальные;
2. проекты общаются как независимые модули — API-first с заделом под брокер сообщений;
3. баланс стоимости и производительности (зарубежный VPS) против комплаенса 152-ФЗ;
4. эволюция архитектуры по измеримым триггерам, а не по ощущению.

## 2. Состояние репозитория на 2026-10-22

| Аспект | Факт | Следствие для развёртывания |
| --- | --- | --- |

| Точка входа сервиса | отсутствует: нет HTTP API, нет CLI-сервиса, только `examples/*.py` | межпроектный API появится не раньше T3.4 ([#17](https://github.com/G-Ivan-A/aether-orbis/issues/17)) |

| Runtime-конфигурация | `configs/runtime/default.yaml`: `workers.concurrency: 4`, `budgets.max_cost_rub: 150`, отдельные `source` / `knowledge` / `retrieval` store | бюджеты и параллелизм уже вынесены из кода — лимиты контейнера согласуются с ними, а не с кодом |
| Секреты | только переменные `AETHER_ORBIS_*` (ADR-003 п. 6) | префикс уже изолирует проект в общем окружении хоста |
| Хранилища | stdlib-адаптеры по умолчанию, опциональный embedded `KuzuGraphStore`; Qdrant и Langfuse — целевые (ADR-001) | embedded-хранилища живут внутри процесса проекта — нет общей СУБД, которую надо делить между проектами |
| Телеметрия | контракт [`telemetry-contract.md`](../standards/telemetry-contract.md), исполняемая запись событий без внешнего бэкенда | контракт позволяет выбрать бэкенд наблюдаемости по ресурсам хоста |

| [#43](https://github.com/G-Ivan-A/aether-orbis/issues/43) | `pyproject.toml` | мягкая предпосылка | выполнить до задачи с `Dockerfile`, а не «после MVP» |
| #9–#15, #19–#23 | фазы 2–4 | не пересекаются | без изменений |

**Порядок фаз.** Фаза 5 (развёртывание) стоит после фазы 4, а общий сервер нужен уже сейчас —
другим проектам. Разрешение: платформенная часть (хост, изоляция, бэкап, мониторинг) — отдельная
задача уровня «платформа», не зависящая от фаз 2–4 AetherOrbis; сам AetherOrbis заезжает на
платформу, когда у него появится точка входа (T3.4).

## 4. Конфликты с действующими ADR

| ID | ADR | Положение | Конфликт с новой вводной | Предложение |
| --- | --- | --- | --- | --- |
| К-1 | [ADR-003](../adr/2026-08-adr-003-infrastructure.md) п. 1–2 (proposed) | serverless-first, VPS — только fallback и носитель состояния | целевая среда — один VPS для всех проектов; serverless-слоя нет | заменить ADR-007 п. 1–2: контейнерный сервис на общем хосте; serverless остаётся триггерной опцией |
| К-2 | ADR-003 п. 3 | хранение **и обработка** — только в РФ; вне РФ — только вызовы моделей без ПДн | гибридный вариант фаундера переносит обработку за рубеж | заменить политикой по классам данных ADR-007 п. 3: ограничение «только РФ» сохраняется для ПДн и данных заказчиков, но не для публичного контента |
| К-3 | ADR-003 п. 4 | 2FA на публичном API | межпроектные вызовы — машина-машина, второго фактора у сервиса нет | уточнить ADR-008 п. 6: 2FA для людей, сервисная аутентификация для сервисов |
| К-4 | ADR-003, «Совместимость и миграция» | «сырой материал — единственный источник, требующий резервного копирования» | противоречит [ADR-004](../adr/2026-09-adr-004-preservation-policy.md) (accepted): потеря извлечённого подграфа дороже хранения, повторный обход не воспроизводит наблюдение | бэкап охватывает acquired artifacts, derived knowledge, observation history и Research Run (ADR-007 п. 5) |
| К-5 | ADR-003, таблица стоимости | 2 vCPU / 4 GB | ориентир для одного проекта; трёх проектов с браузерным обходом он не выдерживает | новый бюджет ресурсов — ADR-007 п. 4 и RFC § Proposal |
| К-6 | [ADR-001](../adr/2026-08-adr-001-tech-stack.md) (proposed), observability — Langfuse | Langfuse self-host | Langfuse v3 требует Postgres, ClickHouse, Redis и S3-хранилище; это сопоставимо с бюджетом одного проекта целиком | Langfuse — отложенный выбор: до триггера телеметрия пишется по контракту в собственный sink проекта; self-host Langfuse — только при выделенном ресурсе |
| К-7 | [ADR-002](../adr/2026-08-adr-002-model-routing.md) (proposed) | приоритет провайдеров РФ и Китая | при зарубежном хосте вызовы RF-провайдеров идут через границу; часть RF-ресурсов закрыта для зарубежных IP | учитывается при выборе юрисдикции хоста (ADR-007 п. 2) |
| — | ADR-004…006 (accepted) | контракты домена | не затрагиваются; Job API (ADR-008) явно отделяет статус задания от исхода прогона ADR-006 | без изменений |

## 5. Внешние факты

### 5.1. 152-ФЗ

| Норма | Содержание | Следствие |
| --- | --- | --- |
| ч. 5 ст. 18 152-ФЗ | при сборе ПДн оператор обеспечивает запись, систематизацию, накопление, хранение, уточнение и извлечение ПДн граждан РФ с использованием баз данных, находящихся на территории РФ ([Habr Q&A с текстом нормы](https://qna.habr.com/q/366966)); по практике требование касается **первичных** операций ([h-cons.ru](https://h-cons.ru/stati/lokalizaciya-personalnyh-dannyh-chto-eto-takoe-i-zachem-ona-nuzhna), [harant.ru](https://harant.ru/questions/q-145519/)) | бэкап в РФ при первичной базе за рубежом **не выполняет** требование; шифрование не заменяет локализацию |
| ст. 12 152-ФЗ (ред. с 01.03.2023) | трансграничная передача — только после уведомления Роскомнадзора; для стран вне перечня «адекватных» — с ограничениями ([pravo.ru](https://pravo.ru/opinion/249956/), [garant.ru](https://www.garant.ru/products/ipo/prime/doc/406038183/)) | обработка ПДн на зарубежном хосте — это трансграничная передача с отдельной процедурой |
| ч. 8 ст. 13.11 КоАП | штраф за нарушение локализации — до 6 млн ₽, повторно — до 18 млн ₽ ([h-cons.ru](https://h-cons.ru/stati/lokalizaciya-personalnyh-dannyh-chto-eto-takoe-i-zachem-ona-nuzhna)) | риск несопоставим с экономией на хостинге |
| 420-ФЗ от 30.11.2024 | оборотные штрафы за утечки ПДн с 30.05.2025 ([Habr](https://habr.com/ru/articles/862744)) | шифрование бэкапов и разграничение доступа — обязательная мера, а не улучшение |
| изменения 2025 г. | источники расходятся, охватывает ли новая редакция ч. 5 ст. 18 и последующие операции за рубежом ([comnews.ru](https://www.comnews.ru/digital-economy/content/241730/2025-10-13/2025-w42/1016/granica-zamke-osobennosti-raboty-personalnymi-dannymi-rossii)) | трактовка требует юридической проверки; проектирование исходит из строгой трактовки |

Оговорка: таблица — инженерная интерпретация публичных источников, а не юридическое заключение.
Действующую редакцию нужно сверить по [pravo.gov.ru](http://pravo.gov.ru) до принятия ADR-007.

**Какие данные проектов являются ПДн.** Учётные записи пользователей API (e-mail, TOTP-секреты)
являются ПДн любого проекта. Репутационное направление AM-2 оперирует субъектами — физическими
лицами. CRM и материалы заказчиков БА-проекта — ПДн и непубличные данные заказчиков. Публичный
контент источников (статьи, посты) может содержать ПДн; его статус зависит от цели обработки.

### 5.2. Провайдеры

Цены — ориентиры на дату документа по сторонним агрегаторам; перед закупкой сверяются с
официальными прайсами.

| Вариант | Конфигурация | Ориентир, ₽/мес | Источник |
| --- | --- | --- | --- |
| Timeweb Cloud «Cloud 160» (РФ) | 8 vCPU / 16 GB / 160 GB NVMe | 2 777 по прайсу 2022 г.; закладывается 3 000–4 000 | [timeweb.com](https://timeweb.com/bonuses/timeweb-cloud-zapustil-novuyu-linejku-tarifov-dlya-vsekh-klientov/) |
| Timeweb Cloud «Cloud 50» (РФ) | 2 vCPU / 4 GB / 50 GB | 555–720 | ADR-003 |
| Contabo Cloud VPS 30 (EU) | 8 vCPU / 24 GB / 200 GB NVMe | €14 (~1 400–1 500 при ~100 ₽/€) | [onedollarvps.com](https://onedollarvps.com/pricing/contabo-pricing) |
| Contabo Cloud VPS 20 (EU) | 6 vCPU / 12 GB / 100 GB NVMe | €7 | там же |
| Объектное S3-хранилище в РФ (Selectel / Timeweb / Yandex) | 100–200 GB зашифрованных бэкапов | ~200–500 | порядок величины; официальные прайсы не проверены |

Нефинансовые факторы Contabo: в выдаче нет площадок в РФ; российские карты и международные
платёжные системы блокируют типовые обходные схемы оплаты
([CB Insights](https://www.cbinsights.com/company/contabo)); санкционный режим ЕС ограничивает
IT-услуги для российских лиц ([Bellerage](https://www.bellerage.com/news/bellerage-vps-services/)).
Отсюда — риск блокировки аккаунта без предупреждения. Это риск **доступности**, а не только
комплаенса: он требует восстановления на другом провайдере за ограниченное время.

Нейтральные юрисдикции (KZ / AM / NL с оплатой в рублях через реселлеров) снимают проблему оплаты,
но не снимают ни ч. 5 ст. 18, ни ст. 12: для ПДн это та же трансграничная передача. Для NL
сохраняется санкционный риск ЕС, у KZ / AM нет ценового преимущества перед РФ.

## 6. Сопутствующие вопросы фаундера из диалога

| Вопрос | Ответ по фактам |
| --- | --- |
| Это микросервисная архитектура? | Нет. Каждый проект — модульный монолит и отдельно развёртываемый сервис; между проектами — контрактный API. Микросервисы внутри проекта при одном разработчике и одном хосте дали бы распределённые отказы без выигрыша в масштабировании |
| ADR или RFC? | По стандарту Хаба: межрепозиторное решение с открытыми альтернативами — сначала RFC, принятое решение фиксируется в ADR. Здесь RFC несёт разбор вариантов, ADR-007/008 — решения |
| Нужен ли международный домен при наличии `open-ai.ru`? | Технически `.ru` работает глобально, и выбор домена не зависит от юрисдикции хостинга. Риск — в имени: `open-ai` сходно до степени смешения с товарным знаком OpenAI. Рекомендуется нейтральное имя платформы; при зарубежной аудитории — `.com` / `.dev`, без `.io` из-за неопределённости статуса Британской территории в Индийском океане |
| «Роутер, управляющий очередями» | Это Job API (ADR-008): одна форма задания поверх HTTP сейчас и поверх брокера потом |
