# Три задачи для запуска первого пилота

B-004, B-005 и B-006 имеют независимые входы и тесты. Их стык — существующие порты
Research Run. Следующий шаг B-007 использует все три результата и отдельно подтверждает
допуск реального источника, модели и среды заказчика. Формат постановок следует стандарту задач
Хаба. [Задача пилота](https://github.com/G-Ivan-A/aether-orbis/issues/52),
[стандарт задач](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/.github/ISSUE_TEMPLATE/task.md).

## B-004 · Model Router

Operating Mode `Hybrid`, Task Type `Implementation`.

1. **User Story.** Как оператор, хочу назначить модели по операциям и видеть счётчики
   вызовов, чтобы управлять качеством, допустимостью и стоимостью пилота.
2. **ФТ.** Система разрешает роль в явно описанный маршрут из runtime YAML и выполняет
   вызов модели через LiteLLM. Извлечение использует тот же порт и проверку доказательств,
   что и локальный адаптер. Ненастроенные роли остаются недоступны для модельных вызовов.
3. **НФТ.** До вызова подтверждаются получатель и точный payload. При отказе система
   возвращает код ошибки без автоматического повтора или fallback. Телеметрия содержит роль,
   маршрут, модель, доступные счётчики и стоимость без содержимого запроса, ответа и секретов.
4. **Задача исполнителю.** Добавить Router, модельный адаптер извлечения, контракт настройки,
   проверку импортов SDK в CI и тесты выбора, отказа и аудита на имитации транспорта.
5. **Ограничения.** Первый маршрут использует явно указанный HTTPS endpoint с совместимым API.
   Допуск фактического получателя, оценка модели и применение к материалам заказчика входят в B-007.

**SSOT.** [Задача #9](https://github.com/G-Ivan-A/aether-orbis/issues/9),
[ADR-002](https://github.com/G-Ivan-A/aether-orbis/blob/main/docs/adr/2026-08-adr-002-model-routing.md),
[ADR-009](https://github.com/G-Ivan-A/aether-orbis/blob/main/docs/adr/2026-10-adr-009-edge-anonymization-and-lean-hybrid.md).

**Приёмка.** Смена alias в YAML выбирает новый маршрут. Отказ в допуске не вызывает транспорт.
Ошибочный ответ не превращается в доказательство. Вне Router импорт SDK блокируется тестом CI.

## B-005 · YAML-профили направлений

Operating Mode `Hybrid`, Task Type `Implementation`.

1. **User Story.** Как оператор, хочу запускать другое направление из YAML, чтобы менять
   предмет, набор источников и политику отбора без правки модулей.
2. **ФТ.** Система загружает профиль и runtime отдельно, строит frontier и политику из
   спецификации и записывает ID и версии реально использованных настроек в Research Run.
3. **НФТ.** Несовместимая конфигурация отклоняется до вызова портов. CI валидирует отслеживаемые
   профили. Одинаковая команда запускает разные направления на локальных корпусах.
4. **Задача исполнителю.** Подключить существующий валидатор на входе запуска, собрать
   общую конфигурацию адаптеров и проверить запуск по двум независимым YAML-профилям.
5. **Ограничения.** Сохранить прежние оффлайн-прогоны. Конфигурации и материалы заказчика
   загружаются с локального пути в его контуре.

**SSOT.** [Задача #12](https://github.com/G-Ivan-A/aether-orbis/issues/12),
[ADR-006](https://github.com/G-Ivan-A/aether-orbis/blob/main/docs/adr/2026-09-adr-006-research-specification.md),
[контракт спецификации](https://github.com/G-Ivan-A/aether-orbis/blob/main/docs/standards/research-specification-contract.md).

**Приёмка.** Два YAML-профиля дают собственные frontier, версии и решения. Нарушение
схемы прекращает запуск до чтения корпуса. Оффлайн-сценарии AM-1 и AM-2 продолжают проходить.

## B-006 · HTTP/RSS для AM-1

Operating Mode `Hybrid`, Task Type `Implementation`.

1. **User Story.** Как оператор, хочу получить ограниченную тематическую подборку,
   чтобы проверять практики с источниками без ручного копирования статей.
2. **ФТ.** Система принимает манифест одобренных URL и опциональную RSS-ленту Хабра.
   Повторная ссылка обрабатывается один раз. Допущенная статья поступает в существующий
   SourceFetcher-контур с каноническим URL. Отказ виден оператору и учтён в исходе.
3. **НФТ.** Запросы ограничены HTTPS, временем, задержкой, числом URL/перенаправлений
   и размером ответа. До каждого запроса материала проверяются допуск и robots.
   Запрет источника, 403/429, переход на другой сайт и неоднозначная политика блокируют запросы.
4. **Задача исполнителю.** Добавить адаптер, конфигурацию манифеста и тесты для RSS, дедупа,
   частичного сбора, отказа и безопасной телеметрии на синтетическом HTTP.
5. **Ограничения.** Только разрешённые публичные статьи. Живой режим запускается по
   разрешению в B-007. RSS служит обнаружению ссылок. Источники с учётной записью,
   браузер и универсальный поиск вне объёма.

**SSOT.** [Задача #51](https://github.com/G-Ivan-A/aether-orbis/issues/51),
[анализ пилота](https://github.com/G-Ivan-A/aether-orbis/blob/main/docs/analysis/2026-11-22-customer-pilot-readiness.md),
[контракт достаточности](https://github.com/G-Ivan-A/aether-orbis/blob/main/docs/standards/sufficiency-gate-contract.md).

**Приёмка.** HTTP-фикстуры покрывают манифест, RSS и дедуп. Запрет или сетевая ошибка
дают `PARTIAL` при наличии квалифицированного результата или `ZERO` без него. Техническая
телеметрия содержит коды причин без URL, сырых ответов и данных авторов.
