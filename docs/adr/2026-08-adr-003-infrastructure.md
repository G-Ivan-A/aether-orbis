## Context

Вычислительная часть пайплайна опирается на сильные модели. VPS доступного класса не способен
разместить модели уровня ≥ 27B параметров, поэтому попытка «сделать всё на своём сервере» либо
упирается в слабые локальные модели, либо требует стоимости, несопоставимой с MVP.

Одновременно система обязана хранить состояние: графовое и векторное хранилища, сырой материал
источников, телеметрию. Это плохо ложится на serverless.

Дополнительные ограничения: обработка данных в юрисдикции РФ (152-ФЗ) и публичный API, доступ к
которому нельзя оставлять на одном лишь ключе.

Стоимость VPS в оценках SSOT была уточнена: первоначальная оценка ~500 ₽/мес занижена.

| Провайдер | Конфигурация | Ориентир, ₽/мес |
| --- | --- | --- |
| Timeweb Cloud «Cloud 50» | 2 vCPU / 4 GB / 50 GB NVMe | 555–720 |
| Selectel VDS 2-4-50 | 2 vCPU / 4 GB / 50 GB | 650–750 |
| Yandex Cloud standard-v3 (эквивалент) | 2 vCPU / 4 GB | 2 800–3 300 |

Скрытые статьи расходов: статический публичный IP (~100–150 ₽/мес в Yandex Cloud), исходящий трафик,
снапшоты (~50–100 ₽/мес), домен и SSL.

> **Конфликт К-5 (issue #44).** Таблица рассчитана на один проект. Для общего хоста трёх проектов
> бюджет ресурсов и стоимость — в [RFC § 2, § 4](../rfc/2026-10-multi-project-vps-platform.md#proposal);
> конфигурация 2 vCPU / 4 GB остаётся ориентиром для узла D2 или одного проекта.

## Decision

1. **Serverless-first** для вычислительных, безсостояточных шагов: ingestion-воркеры,
   extraction-воркеры, API-слой. Основание — доступ к сильным моделям и оплата по факту вызовов.
2. **VPS как fallback и как носитель состояния**: графовое хранилище, векторный индекс, объектное
   хранилище сырого материала, observability. VPS выбирается из уточнённой таблицы стоимости выше;
   при бюджетировании учитываются скрытые статьи расходов.

   > **Конфликт К-1 (issue #44).** Целевая среда — один VPS для нескольких проектов, serverless-слоя
   > нет. Предложенная замена п. 1–2 — [ADR-007](2026-10-adr-007-multi-project-deployment-topology.md)
   > п. 1, 4: контейнерный сервис на общем хосте; serverless — опция по триггеру.
3. **Юрисдикция РФ** для хранения и обработки данных (152-ФЗ). Провайдеры вне РФ допускаются только
   для вызовов моделей, не сопровождающихся передачей персональных данных.

   > **Конфликт К-2 (issue #44).** Гибридный вариант фаундера переносит обработку за рубеж.
   > Предложенная замена — размещение по классам данных ADR-007 п. 2–3: D2 (ПДн, данные заказчиков) —
   > только в РФ, как и сейчас; ступень 0 целиком в РФ; зарубежный хост — только для D0/D1 по
   > триггеру.
4. **Публичный API защищается обязательной 2FA** — TOTP либо внешний IAM-провайдер. Ключ API без
   второго фактора недостаточен для доступа к публичным эндпоинтам.

   > **Конфликт К-3 (issue #44).** У межпроектных вызовов машина-машина нет второго фактора.
   > Предложенное уточнение — [ADR-008](2026-10-adr-008-inter-project-api-contract.md) п. 6: 2FA для
   > людей, per-caller учётные данные и mTLS для сервисов.
5. **Репозиторий и runtime-данные разделены.** В git **НЕ ДОЛЖНЫ** попадать: базы данных, сырой и
   извлечённый контент источников, секреты и ключи, артефакты прогонов, логи и телеметрия, кэши
   моделей. Правило закреплено в [`.gitignore`](../../.gitignore) и в
   [`docs/concept.md`](../concept.md), раздел 7.
6. Секреты передаются через переменные окружения или менеджер секретов провайдера; формат имён —
   `AETHER_ORBIS_*`.

## Decision Drivers

- Сильные модели недостижимы на VPS доступного класса — это определяющее ограничение.
- Оплата по факту вызовов соответствует неравномерной нагрузке исследовательских прогонов.
- Состояние требует постоянного диска и предсказуемой латентности — это зона VPS.
- 152-ФЗ ограничивает размещение данных.
- Публичный API без второго фактора — неприемлемый риск при утечке ключа.
- Риск «слишком тяжёлой инфраструктуры на старте» зафиксирован в SSOT.

## Alternatives Considered

| Альтернатива | Почему отклонена |
| --- | --- |
| Всё на VPS, включая инференс | VPS доступного класса не тянет модели ≥ 27B; качество извлечения и анализа деградирует. |
| Всё serverless, включая состояние | Графовое и векторное хранилища требуют постоянного диска; холодные старты и лимиты выполнения ломают обходы. |
| Managed Kubernetes с самого начала | Стоимость и эксплуатационная сложность несопоставимы с MVP из двух направлений. |
| Локальный запуск без публичного API | Не выполняет требование доступности API для потребителей. |
| API только с ключом, без 2FA | Один скомпрометированный ключ даёт полный доступ. |

## Consequences

**Положительные**

- Доступ к сильным моделям без капитальных затрат.
- Стоимость простоя близка к стоимости одного VPS.
- Чёткая граница «репозиторий описывает — runtime исполняет».

**Отрицательные и риски**

- Две среды исполнения вместо одной — выше сложность развёртывания; митигируется тем, что граница
  проходит ровно по признаку наличия состояния.
- Холодные старты serverless увеличивают латентность; для исследовательских прогонов не критично.
- Стоимость VPS выше первоначальной оценки; заложена уточнённая таблица со скрытыми расходами.
- 2FA усложняет интеграцию клиентов; компенсируется поддержкой IAM-провайдера.

**Совместимость и миграция (Archetype C)**

- Совместимость: контракты компонентов не зависят от среды исполнения; тот же код запускается
  локально, в serverless и на VPS.
- Миграция: перенос состояния между провайдерами выполняется восстановлением из Raw / Source Store и
  снапшотов; сырой материал — единственный источник, требующий резервного копирования.

  > **Конфликт К-4 (issue #44).** Утверждение противоречит принятому
  > [ADR-004](2026-09-adr-004-preservation-policy.md): потеря derived knowledge и observation history
  > невосстановима повторным обходом. Предложенная замена — ADR-007 п. 5: бэкапу подлежат все три
  > измерения ADR-004 и Research Run.
- Runtime-валидация: проверка доступности API с включённой 2FA и проверка отсутствия runtime-данных
  в git перед каждым релизом.

## Compliance and Validation

| Проверка | Как выполняется |
| --- | --- |
| Runtime-данные отсутствуют в репозитории | правила `.gitignore` + проверка в CI |
| Секреты не попадают в коммиты | secret scanning в CI |
| Публичные эндпоинты требуют 2FA | интеграционный тест авторизации |
| Данные размещены в юрисдикции РФ | проверка региона ресурсов при развёртывании |
| Бюджет инфраструктуры соответствует оценке | ежемесячная сверка со сводкой телеметрии затрат |

## Lifecycle

Пересматривается при изменении доступности провайдеров моделей из РФ, при выходе за рамки бюджета
инфраструктуры более чем на 50 %, а также перед фазой 5 (Deploy) роадмапа.

Пересмотр инициирован issue [#44](https://github.com/G-Ivan-A/aether-orbis/issues/44): при принятии
ADR-007 и ADR-008 этот ADR получает новую версию, в которой п. 1–4 и раздел миграции заменяются
ссылками на них (поле Superseded by — частичное замещение); п. 5–6 сохраняют силу, статус ADR не
меняется на `superseded`, пока в нём остаются действующие пункты.
