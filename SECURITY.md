# Security Policy — AetherOrbis

## Границы данных

Репозиторий не хранит runtime-данные. Вне git находятся: базы данных (graph, vector, реляционные),
сырой и извлечённый контент источников, секреты и ключи API, артефакты прогонов, логи и телеметрия,
кэши моделей. Правило закреплено в [`.gitignore`](.gitignore) и
[ADR-003](docs/adr/2026-08-adr-003-infrastructure.md).

## Секреты

- Передаются переменными окружения `AETHER_ORBIS_*` или менеджером секретов провайдера.
- Не коммитятся ни в каком виде, включая примеры и фикстуры.
- Файлы `.env*` игнорируются git.

## Доступ к публичному API

Публичные эндпоинты требуют **обязательной 2FA** — TOTP либо внешнего IAM-провайдера. Ключ API без
второго фактора недостаточен.

## Юрисдикция

Хранение и обработка данных — в юрисдикции РФ (152-ФЗ). Провайдеры вне РФ допускаются только для
вызовов моделей без передачи персональных данных.

При принятии [ADR-009](docs/adr/2026-10-adr-009-edge-anonymization-and-lean-hybrid.md) (proposed,
issue #46) правило уточняется: сбор и все записи об отдельных людях остаются в РФ, а зарубежный
вычислительный узел получает только агрегаты и очищенный от идентификаторов контент. Требования
субъектов о прекращении обработки исполняются в течение 3 рабочих дней, об уничтожении — в течение
10 рабочих дней.

## Сообщение об уязвимости

Уязвимости сообщаются приватно владельцу репозитория (G-Ivan-A) через GitHub Security Advisories.
Публичные issue для уязвимостей не используются.

## При компрометации секрета

1. Немедленно отозвать ключ у провайдера.
2. Проверить историю git на предмет попадания секрета в коммиты.
3. Зафиксировать инцидент в issue без раскрытия самого секрета.
